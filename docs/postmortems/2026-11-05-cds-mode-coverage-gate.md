# 目的基因模式的两个正确性前提（2026-11-05）

> 单样品测序新增「目的基因模式」（v2.37.0-alpha.1）：按文件名从参考图谱定位
> 目的 CDS，以「CDS ± 150bp 侧翼」线性区段为参考分析。开发过程中真实数据
> 回归连抓两个「给错结论」级问题，本文留档防回潮。

## 现象

1. **零侧翼实现吞掉边界变异**：以纯 CDS 编码序列（无任何上下文）为参考跑
   真实 MX 数据时，参考坐标 5076 的插入变异（落在 CDS 第 2 位、medium 置信）
   未被检出；`protein_identical` 由全质粒模式的 False 翻成 True——验证工具
   给出「蛋白一致」的错误结论。
2. **覆盖资格缺失**（旧方案一直存在，本次一并修）：read 全部只比对到侧翼/
   骨架、目的 CDS 零覆盖时，变体列表为空 → 结论头照样输出干净的
   「✓ 构建与设计一致」——引物没测到目标却报通过。

## 根因

1. 局部比对对参考**边界**的软剪切是零成本的：贴着参考首尾的插入/缺失会被
   leading/trailing clip 吸收而不产生 gap 证据。全质粒模式下 CDS 深居参考
   内部感受不到；CDS-only 参考把 CDS 首尾推到了参考边界，边界变异必然丢。
2. `_conclusion_summary` 的「无确认差异 → ✓」分支只看变体与蛋白判定，
   从不问「分析目标到底被 read 覆盖了没有」；未覆盖 CDS 的 cds_report
   虽有 `protein_identical: None` 与「未测」verdict，但只在卡片里，
   结论头看不见。

## 修法

1. **侧翼是正确性前提，不是可选优化**：`cds_extract.resolve_reference`
   提取 CDS ± `FLANK_BP=150` 参考侧翼（负链整段反向互补成编码方向），
   侧翼以 5′/3′ misc_feature 标注。修后 CDS 模式与全质粒模式的变体集合
   逐一相等（真实 MX 数据四变异全部对上）。
2. **结论覆盖资格门**：伪 CDS 特征带 `analysis_target: True` 机器标记，
   经 `_build_cds_reports` 传入报告；`_conclusion_summary` 据此——
   零覆盖 → 结论头强制降级「△ 未被任何 read 覆盖，未能验证」（✓ 拦截）；
   部分覆盖 → 任何结论追加「目的 CDS 覆盖 X%（未覆盖部分未验证）」。
   前端 `findCdsTarget` 与管线同用此标记（description 前缀兜底旧记录）。

## 验证

- 真实数据回归新增 `test_real_cds_mode_mx`：变体集合平移后与全质粒模式
  逐一相等 + 蛋白判定相等——这是等价性锁，改口径必红。
- `test_cds_mode.py` 资格门单测 6 项（零覆盖 △/✗+提示/部分覆盖提示/
  完整覆盖逐字不变/无标记逐字不变）+ 端到端「read 全落 3′ 侧翼」用例。
- 全量：pytest 1850 passed / vitest 686 passed / 门禁全绿。

## 教训

- **新模式换了参考，就换了一套边界条件**：凡是「从大序列里截一段当参考」
  的模式，截取边界就是新的比对阵地，必须留上下文锚定；截完要和原口径做
  变体集合等价回归，等价锁不过 = 模式有病。
- **✓ 是资格判定不是默认值**：结论头给「通过」之前要问「目标被测到了吗」，
  未覆盖区域的「未检出差异」不是通过证据。批量页已有
  `MIN_VERDICT_COVERED_BP` 同型守门（2026-10 即已存在），单样品此番补齐。
