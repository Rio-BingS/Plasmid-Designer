- **审计对象**：github.com/Rio-BingS/Plasmid-Designer，提交 `bd5dff4`（v2.36.0，2026-11-04）
- **审计范围**：AB1 解析 → 基线校正/质量修剪/可信区 → 比对（含环状）→ 变异检出与置信度 → 双峰/混合 → poly 同聚物 → 共识与 CDS 判读 → 结论文本、批量 Excel、整理包、前端峰图联动
- **审计日期**：2026-11-06

## 0. 结论先行

这套管线在工程细节上做得非常用心（FWO_1 通道映射、反向 read 坐标镜像、环状参考延长比对、k-mer 种子加速、indel 最左归一化、跨引物互检、poly 峰图计数等都已实现，反向 read 与跨原点 read 的实测均正确）。但它的**判读哲学存在一个系统性缺陷**：

> **“证据不足 = 与设计一致”。** 凡被判为低置信的差异，一律从结论、CDS 判读和共识序列中剔除，共识位点回填参考碱基，顶部摘要给出 ✓。而“低置信”的触发条件大量是**与该位点真实性无关的固定先验**（read 坐标 >700bp、固定 30% 次峰阈值、单点双峰不计数、软剪切即“未覆盖”）。

这导致两类相反的错误同时存在：

- **漏报（假 ✓）**：实测中，一处 Q50、突变峰占比 100%、信噪比 238 的错义突变仅因位于 read 第 765bp，结论为“✓ 构建与设计一致”，共识序列被回填为参考碱基；35% 与 50:50 的混合克隆点突变结论为“✓ 未检出差异”；read 5′ 端紧邻引物的 175bp 错误连接序列结论为“✓ 未检出差异”；启动子确证突变在批量 Excel 中被判“合格”并归入“正确”文件夹。
- **误报（假 △）**：两条公开的高质量真实 AB1（Biopython 测试集 3730.ab1 / 3100.ab1，后者 A 级、平均 Q53.6）都被判为“疑似混合样品——建议重新挑单克隆复测”。

而为了弥补这两类错误，系统输出了大量“建议人工核对峰图”（pipeline.py 中出现 25 处）、长达数十行的自由文本结论，并把低置信项默认折叠——**这正是人工复核负担的根源**：机器既不敢下结论，又把最该看的东西藏起来。

| 严重度 | 数量 | 代表问题 |
|---|---|---|
| 高 | 10 | 低置信即排除+共识回填参考；固定可信区；固定次峰阈值；单点双峰静默；软剪切吞掉端部差异；非 CDS 元件无判读；部分覆盖即合格；结论摘要不汇总阻断项；文本驱动逻辑；坐标映射不一致 |
| 中 | 13 | SNR 分母失效；无 PCON 文件被拒；多 read 证据只取首条；ORF 自动校正越界；tracy 解卷积文件名不匹配；质量不感知比对；无重叠区不一致报告；三出口口径不一致等 |
| 低 | 4 | PLOC −1 偏移；次峰碱基 None；同密码子多替换注释；核心层默认线性 |

## 审计方法

1. 克隆仓库并通读全部相关代码（约 1.55 万行）：`core/sanger/*`（abif_reader、signal、aligner、pipeline 2871 行、homopolymer、reliable_zone、annotator、batch）、`app/sequencing_*`、`routes/sequencing_*`、`scripts/batch_sequencing_report.py`、前端 `SequencingPanel` 及 `components/sequencing/*`、`useSeqViz.ts`、`docs/KNOWN_ISSUES.md`。
2. 实测：安装 biopython 1.88，直接调用 `core.sanger.pipeline.analyze()`。数据分两类：

    - **真实 AB1**：Biopython 官方测试集 `3730.ab1`（1165bp）、`3100.ab1`（795bp）、`310.ab1`（868bp，无质量值）。以 read 自身碱基作为“真值”嵌入 1.5kb 随机骨架构造参考，再在参考上制造差异，模拟“克隆与设计不符”。
    - **合成 AB1**：用仓库自带 `tests/abif_utils.make_ab1` + 自写高斯峰生成器（12 采样点/碱基、随机振幅、噪声），制造指定比例的混合克隆。

3. 每个结论落到 文件:行号；能实测的均给出实测结果（附录 A）。

## 第一层　原始信号解析与预处理

### 1.1【高】read 可信区由固定坐标先验决定，>700bp 的高质量差异被强制判低置信

**代码证据**

- `core/sanger/reliable_zone.py:37-41` 默认 `front_hard=30, front_gray=60, tail_gray=700, tail_hard=900`。
- `reliable_zone.py:180-185` 尾端起点固定为 `hi_raw = params.tail_gray`，信号只能把边界往里收（第 185-196 行的衰减检测仅在 `< tail_gray` 内搜索），**即使 700bp 之后 Q 值持续 50，也不会外扩**。
- `pipeline.py:194-195`：
```python
if zone and rp and support < 2 and not in_zone(zone, rp):
    return "low"
```

**实测（附录 A-B）**：3730.ab1 在原始第 780bp 处 Q 值为 50（窗口内全部 Q50），在参考上制造一个错义突变（GeneX:S60R）：

- 变体：`T>G, Q50, mutant_pct 100%, SNR 238.1, conf=low`，原因“位于 read 尾端灰区 701–900bp”；
- 结论首行：**`✓ 结论：构建与设计一致（1 处低置信差异疑似测序伪影，未计入判定）`**；
- CDS：`GeneX 蛋白与设计一致`；
- 共识序列该位输出参考碱基 `T`，而 read 实测为 `G`。

**影响**：漏报（假 ✓）+ 人工负担（所有长 read 的后 1/3 区段都被打成“需其他引物覆盖”）。3730xl 等现代仪器常规可读到 900–1000bp，700bp 先验把约 25-30% 的有效数据作废。

**改进方案**

1. 可信区完全由信号决定，位置先验降级为**弱先验**：按 20bp 滑窗计算 `mean Q`、峰距 CV、半高宽比、主次峰比，满足阈值即可信，不设 700bp 硬顶；`tail_hard` 只作为“无峰图时”的兜底。
2. 位置不再直接决定置信度，而是作为一个**特征**进入后验评分（见 5.3）：`P(error) = f(Q, 峰比, SNR, 局部峰距异常, read 位置)`。
3. 按仪器型号（ABIF `MODL`/`MCHN` 标签）和批次统计 Q-实际错误率曲线做校准。

### 1.2【中】SNR 的噪声分母取整条通道中位数，常为 0，导致 SNR 失效并被当作“信号响亮”

**代码证据**：`pipeline.py:94-110`
```python
rest = ch[:lo] + ch[hi:]
noise = sorted(rest)[len(rest) // 2]
return round(peak / noise, 1) if noise > 0 else None
```
`pipeline.py:226`：`loud = snr is None or snr >= 10` —— SNR 缺失时默认判为“响亮”。

**实测**：3730.ab1 四通道全轨迹中位数：A=2、C=10、G=7、**T=0**（基线校正前后相同）。任何突变碱基为 T 的位点 SNR 都返回 None；实验 A 中高置信替换的 `snr` 字段即为 None。

**影响**：误报（SNR 门槛形同虚设，`snr < 5 → low` 永不触发于 T 通道），同时 SNR 作为置信特征在不同通道上不可比。

**改进方案**：噪声取**局部**（±10 个峰）非调用通道在峰窗内的残差，用 MAD 估计：`noise = 1.4826 × MAD(局部非主通道峰窗面积)`，并设下限 `max(noise, 1)`；SNR 缺失时按“不确定”处理而不是“响亮”。

---

### 1.3【中】质量修剪：无质量值的文件被直接拒绝；单一最大子段可能切掉半条 read

**代码证据**：`pipeline.py:444-460` Mott/Kadane 只保留**单一**累计分最大子段；`pipeline.py:1702-1711` 修剪后 <50bp 即报错返回。

**实测**：`310.ab1`（ABI 310 老仪器，无 PCON 质量记录）提取后 mean Q = 0.0，整个文件将以“Q≥20 的碱基不足 50bp”被拒绝，尽管其峰图完全可用。

**改进方案**：
- 无 PCON 时自动回退到 tracy basecall（镜像里已内置）或按峰型估算 Q；
- 修剪阈值改为错误概率口径（如 phred 的 0.05/碱基），并对 read 中段的低质量凹陷**做掩蔽而不是截断**，避免 poly 区一个低谷把下游几百 bp 整段丢掉。

---

### 1.4【低】PLOC 坐标被错误地减 1

**代码证据**：`abif_reader.py:286`、`abif_reader.py:339`
```python
peak_indices = [int(p) - 1 for p in ploc[: len(bases)]]  # 1-based → 0-based
```
**实测**：3730.ab1 中，调用通道峰顶相对 **原始 PLOC** 的偏移分布为：0（865 个）、+1（268）、−1（仅 9 个）。即 PLOC 已是 0-based 峰顶，减 1 后系统性落在峰顶左侧 1 个采样点。3100.ab1 同样：0 偏移 505 个、−1 仅 18 个。

**影响**：峰窗对称性被破坏；在峰距仅 10-12 采样点的高分辨区，窗口会多吃左邻峰尾部，抬高次峰比，间接推高双峰误报。

**改进方案**：删除 `- 1`；tracy JSON 的 `basecallPos`（pipeline.py:799 同样减 1）需按 tracy 文档确认基准后统一。

---

### 1.5【中】反向 read：方向判定与坐标镜像正确，但缺“引物期望位置/方向”校验

**正面结论**：`aligner.py:312` 正反两向各比一次取高分，`aligner.py:392-395` 把变体 `read_pos` 镜像回电泳坐标，`pipeline.py:1896-1900` 峰证据取互补碱基。实测（附录 A-R）反向 read 的替换以 `mutant_pct 95.7%`、高置信正确检出。

**问题**：方向完全由比对分数决定，`aligner.py:300-307` 同分时取 '+'。系统从不使用引物名/引物序列，因此无法发现：用错引物、引物结合在非预期位置（例如插入片段反向克隆时 read 仍以高分比对到“错误方向”）、样品混淆。

**改进方案**：批量信息表已有引物列（`batch.py` 克隆模式），应建立引物库（名称→序列），校验 read 起点 ≈ 引物 3′ 下游、方向一致；不一致直接给出“引物/方向异常”结论，而不是静默接受。

## 第二层　序列比对

### 2.1【高】局部比对的软剪切把端部真实差异变成“未覆盖”，80% 比例阈值兜不住

**代码证据**

- `aligner.py:23-28` 使用 `PairwiseAligner(mode="local")`，match +2 / mismatch −4 / gap open −6 / extend −2。
- `pipeline.py:394` `PARTIAL_ALIGN_RATIO = 0.8`；`pipeline.py:417-432` 只有比对长度 < 修剪后长度的 80% 才提示“部分比对”。
- 软剪切掉的碱基不产生任何变体，覆盖区间只按 `ref_start..ref_end` 计算。

**实测**（附录 A-E、A-E2）：

| 场景 | 结果 |
|---|---|
| read 5′ 端紧邻引物处 175bp 与设计不同（模拟连接/junction 错误），Q 全部 ≥20 | 比对 898/1073bp（83.7%），**`✓ 结论：构建与设计一致，未检出差异`**，覆盖起点后移 175bp |
| read 3′ 端 188bp 与设计不同 | 比对 885/1073bp（82.5%），**`✓ 构建与设计一致，未检出差异`** |

**影响**：漏报。克隆验证最关键的就是**插入片段与载体的连接处**，而连接处恰恰位于 read 端部；端部错误被解释为“没测到”。

**改进方案**

1. 改为 **glocal（半全局）比对**：read 的高质量区（可信区内）必须端到端比对，只允许低质量端自由悬空；或保留局部比对，但把“软剪切掉的高质量碱基数”作为一等公民输出。
2. 判定规则改为**绝对量**：可信区内被软剪切的碱基 ≥ 15bp 即生成 `unaligned_hq_segment` 差异（类型“连接/结构异常”），进入结论阻断项，而不是用 80% 比例。
3. 对软剪切段做二次比对（split-read）：比对到参考别处 → 报重排/反向插入；比对不上 → 报“未知序列”。

> 补充（正面）：实测 300bp 缺失、150bp 插入在两侧 flank ≥ 450bp 时都能以单个 indel 高置信检出（附录 A-C/D）；但当 flank 较短时，线性 gap 成本（300bp 缺失约 −604 分）会让局部比对宁可软剪切，退化为上面的漏报。split-read 方案同时解决这个问题。

### 2.2【中-高】read↔参考坐标映射存在三套实现，其中两套忽略软剪切偏移

**代码证据**

- 正确的一套：`homopolymer.py:336-397` `_read_ref_maps` 明确使用 `query_start/query_end`（注释“终审 A-20”），前端 `seqPanelModel.ts:92-100` 同口径。
- 错误一：`pipeline.py:1801-1806`（`_signal_analysis_pass`，滑移 echo / 骤降 / 合并压缩区窗口）
```python
if aln["direction"] == "-":
    i0 = aln["ref_end"] - (run["end"] + off)
else:
    i0 = (run["start"] + off) - aln["ref_start"]
```
  默认 read 下标 0 对应 `ref_start`，既不加软剪切偏移，也不考虑上游 indel。
- 错误二：`homopolymer.py:293-315`（`_aligned_run_window`，poly 峰图计数窗口）`idx` 从比对块第 0 列起算，返回值被当作修剪后 read 下标使用，同样缺 `query_start` 偏移；反向时 `total` 是比对块内 read 碱基数而非 read 长度。

**影响**：只要 read 首端被软剪切（实验 E2 中为 175bp），poly 结构的滑移 echo、骤降、合并压缩区、峰图计数就会在**错误的峰窗**上计算，进而错误地抑制或放出双峰与 indel（误报与漏报都可能）。

**改进方案**：每条 read 只计算一次 `ReadRefMap`（含 read→ref、ref→read、软剪切偏移、插入列），所有下游（信号层、poly、互检、前端）都通过它取坐标；删掉所有线性偏移推算。加回归测试：构造首端软剪切 + poly 区的 read，断言三处窗口一致。

### 2.3【中】比对打分对 Sanger 质量与波形畸变完全无感

**代码证据**：`aligner.py:276-292` 的 `quality` 参数只用于生成 `q_aligned` 展示列（第 407-414 行），从不参与打分；mismatch −4 对 Q10 与 Q60 一视同仁。

**影响**：GC 压缩、峰合并区的低质量调用会以同样代价拉扯 gap 位置，产生错位 indel+错配簇（下游依赖互检与 poly 规则事后去噪，规则越加越多）。

**改进方案**：
- 短期：Q 加权打分，`mismatch = −4 × w(Q)`、`w(Q)=min(1, Q/30)`，N/低 Q 碱基近似通配；
- 中期：直接使用 tracy 的 **trace profile-to-sequence 比对**（tracy align，已在镜像中），它把四通道信号当概率剖面比对，天然吸收压缩与混合峰；或实现 pairHMM。

---

### 2.4【低】环状处理：路由层正确，核心层默认线性

**正面结论**：`aligner.py:467-505` 以“参考 + 参考头部”延长比对，实测跨原点 read 在 `circular=True` 时完整比对、无假缺失（附录 A-F）；`circular=False` 时正确提示“部分比对”。

**风险**：`pipeline.py:2679` `analyze(..., circular=False)` 为核心默认值，只有路由层 `sequencing_routes.py:363`、`sequencing_batch.py:31-35` 改为默认环状。离线脚本或未来新入口直接调核心时会退回线性。另外 `sequencing_endpoints.py:207` 以 `insert_start != 1` 推断拓扑，属启发式。

**改进方案**：拓扑作为参考对象的必填属性（GenBank LOCUS / SnapGene 拓扑字段，FASTA 默认环状并在报告中声明），核心函数去掉默认值强制传入。

## 第三层　变异检出与噪音过滤

### 3.1【高】混合/杂合判定使用固定 30% 次峰阈值 + 固定位点数，真实高质量 read 被判“疑似混合”

**代码证据**：`pipeline.py:61-64`
```python
MIXED_PEAK_RATIO = 0.30
MIXED_WIDESPREAD_MIN = 5
MIXED_SCATTERED_MIN = 2
MIXED_STRETCH_MIN = 8
```
`pipeline.py:519` `if ratio > MIXED_PEAK_RATIO`，`pipeline.py:680` `count >= MIXED_WIDESPREAD_MIN → widespread`。阈值与 read 长度、位置、通道、批次均无关。

**实测**（附录 A-基线、A-阈值扫描）

| 文件 | read 质量 | 可信区内 >30% 次峰位点 | 管线结论 |
|---|---|---|---|
| 3730.ab1 | Q20 比例高，mean Q 44.8 | 6 处，比值 0.305-0.385，**全部位于修剪后 50-125bp，6 处中 5 处次级碱基为 A** | △ 疑似混合样品，建议重新挑单克隆 |
| 3100.ab1 | **A 级，mean Q 53.6** | 61 处，**集中在 470-667bp**（信号衰减段） | △ 疑似混合样品，建议重新挑单克隆 |

阈值敏感性（3730 / 3100）：0.25→6/66，0.30→6/65，0.35→1/53，0.40→0/37。3730 的 6 个位点全部挤在 0.30-0.39 这条窄带上——这是 ABI 染料（G 峰后的 A 通道肩峰等）的系统性背景，不是混合克隆；3100 的位点随读长单调增多，是峰展宽的典型形态。真实混合样品的双峰应**从 read 前段就均匀出现、且次要组分占比稳定**。

**影响**：误报（建议用户重新挑克隆，浪费实验周期），并通过 3.3 的链条把相关位点的真实差异降为低置信。

**改进方案（自适应背景模型）**

1. 对每条 read 按 ±25 个峰的滑窗、**分通道对**（主→次，如 G→A）估计次峰比的局部分布（中位数 + MAD）；位点判为双峰需满足 `ratio > local_median + k·MAD` 且 `ratio > 0.2`。
2. read 级“混合”需满足：双峰密度显著高于该 read 自身背景、**次要组分占比在位点间一致**（变异系数小）、且前中后段均有分布；集中在单一区段的按“局部信号问题”处理。
3. 位点数阈值按可信区长度归一（每 100bp 的密度），而不是绝对 5 个。
4. 用一批已知纯克隆/已知混合的真实数据做 ROC 校准，参数按仪器型号存表。

### 3.2【高】单个双峰位点（含真实杂合/混合突变）完全静默

**代码证据**

- 变体只来自主峰碱基调用的比对（`aligner.py:367-387`），次峰碱基从不与参考比较。
- `pipeline.py:628-639` 注释写明：“none：无或仅 1 个位点（单点双峰与个别碱基噪声无法区分，交由该位点变体的峰级证据）”——但当主峰 = 参考碱基时**根本不存在变体**，也就没有“该位点的峰级证据”可交。
- `pipeline.py:221-222`：即使次要等位成为主峰，`mutant_pct < 70 → low`。

**实测**（合成 AB1，附录 A-混合）：在 CDS 内一个位点制造混合克隆

| 混合比例 | 管线结论 |
|---|---|
| 35% 突变 | **`✓ 结论：构建与设计一致，未检出差异`**（mixed_detail 记录了 ratio 0.499，但不进入任何结论） |
| 50:50 | **`✓ 结论：构建与设计一致，未检出差异`**（ratio 0.905） |
| 65% 突变（主峰为突变） | `✓ 构建与设计一致（1 处低置信差异疑似测序伪影）`，CDS“不影响以上判定” |
| 100% 突变（对照） | ✗ 检出 1 处确认差异（高置信） |

**影响**：漏报。混合克隆、未纯化单克隆、PCR 产物测序中的杂合位点，恰好是“最不该放过”的情形。

**改进方案**

1. 对每个次峰显著的位点，取 `{主碱基, 次碱基}` 与参考比较；若次碱基 ≠ 参考，生成 `mixed_variant` 记录，带等位比例 `AF = 次/(主+次)`。
2. 结论规则：CDS/关键元件内任何 `AF ≥ 15%` 且通过 3.1 背景检验的非参考等位 → 结论至少为“△ 待定：疑似混合”，绝不给 ✓。
3. 用 tracy `basecall -f json` 的 `secondarySeq`（`pipeline.py:777-805` 已解析，但目前只做“印证标签”）作为第二个独立来源。

### 3.3【高】“低置信 = 排除”：从结论、CDS、共识中整体剔除，共识回填参考碱基

**代码证据**

- `pipeline.py:363`、`pipeline.py:383-385`：
```python
confirmed = [v for v in variants if v.get("confidence") != "low"]
...
if variants:
    return (f"✓ 结论：构建与设计一致"
            f"（{len(variants)} 处低置信差异疑似测序伪影，未计入判定）")
```
- `pipeline.py:1411-1413`：CDS 只用非 low 变体重建蛋白。
- `pipeline.py:2809-2811` + `pipeline.py:999-1001`：low 变体加入 `skip_keys`，该 read 在此位**按参考碱基投票**；即使是单 read 覆盖（`pipeline.py:1052-1053` 号称“以该 read 为准”），共识也被写成参考碱基。

**实测**：见 1.1（Q50/100%/SNR238 → ✓，共识写参考 T 而实测 G）与 3.2（65% 突变 → ✓）。

**影响**：这是漏报的**放大器**——任何把位点误打成 low 的上游规则（可信区、固定阈值、互检弱覆盖、poly 压缩）最终都表现为“✓ 与设计一致”。用户若导出共识序列做后续设计，拿到的是参考而非实测。

**改进方案**

1. 位点状态改为三态：**confirmed（有正证据）/ rejected（有反证据，如高质量互检读出参考）/ unresolved（证据不足）**。只有 rejected 可以从判定中剔除。
2. 顶部摘要：存在 unresolved 且落在 CDS/关键元件 → `△ 待定（N 处需补测或核对）`，绝不给 ✓；`would_change`（`pipeline.py:1539`）为真的 unresolved 必须升级为阻断项。
3. 共识序列在 unresolved 位输出 IUPAC 码（如 K、R）或小写碱基，并在 `segments` 中标注，禁止回填参考。

### 3.4【中】多 read 支持的变体，其峰级证据与双峰判定只取“第一条 read”

**代码证据**：`pipeline.py:2746-2753`
```python
if key in merged:
    merged[key]["support_reads"] += 1
    merged[key]["read_q"] = max(merged[key]["read_q"], v["read_q"])
else:
    merged[key] = {**v, "support_reads": 1}
```
合并后保留首条 read 的 `read`/`read_pos`；`pipeline.py:1891` 用 `by_read.get(v["read"])` 取峰证据与 `mixed_positions`。`read_q` 取最大值，但峰证据取文件顺序第一条——两者来自不同 read。

**影响**：置信度依赖上传顺序；首条 read 在该位点质量差时，双向支持的真实突变仍可能因“该 read 此处双峰”被判 low（第 197-201 行不检查 support）。

**改进方案**：保留 `evidence_by_read: [{read, read_pos, q, mutant_pct, snr, mixed}]`，置信度按**所有支持 read 的联合似然**计算；同时统计“覆盖但未报告”的 read（目前只对 `support_reads == 1` 做互检，见 `pipeline.py:1945`）。

### 3.5【中】物理伪影建模只覆盖 ≥8/20bp 同聚物，其余压缩/拖尾靠事后规则

**代码证据**：`homopolymer.py:17-18` `HOMOPOLYMER_MIN = 20`、`POLY_OBSERVE_MIN = 8`；滑移/骤降/合并压缩全部挂在 poly run 上（`pipeline.py:1792-1836`）。GC 发夹压缩、短同聚物（3-7bp）滑移、染料斑（dye blob，通常在 read 首 60-120bp）没有专门模型，只能落到“可信区”或“跨 read 互检”。

**影响**：误报（短同聚物 1bp indel 单 read 时依赖互检；无第二条 read 时以 Q 值决定，`pipeline.py:232-237`）与人工负担。

**改进方案**：用**峰距异常**作为通用压缩检测器（任意位置峰距 < 0.6×局部中位即标记压缩段），对 dye blob 用“四通道同时出现宽峰、与碱基调用无关”的形态检测；把这些都作为置信度特征，而不是新的 if 分支。

### 3.6【中】tracy 解卷积几乎必然恒为空

**代码证据**：`pipeline.py:695-707` 调用 `tracy decompose -r ref.fasta -o dec sample.ab1` 后查找 `dec.1.fasta / dec.2.fasta / dec_1.fasta / dec_2.fasta`。按 tracy 官方文档（gear-genomics.com/docs/tracy/cli），decompose 的产物是 `outprefix.align1 / outprefix.align2`（以及 json/bcf），不产出上述 fasta。前端 `AlleleCard.vue` 也只展示前 60bp，不与参考比对。

**影响**：“混合样品自动解卷积”功能对用户不可见地失效（本审计环境未安装 tracy，结论基于官方文档，建议在生产镜像中复核一次）。

**改进方案**：解析 `.align1/.align2`（或 `-f json` 输出），把两条等位分别走同一套比对与 CDS 判读，直接回答“主/次克隆各自是否正确”。

## 第四层　全局结构与完整性

### 4.1【高】非 CDS 元件没有判读层：启动子确证突变在批量结论中被判“合格”

**代码证据**

- 只有 `type == "CDS"` 的特征有结构化判读（`pipeline.py:1334`）。启动子、RBS/Kozak、ori、polyA、loxP/att、抗性基因启动子、克隆用酶切位点都只有“所在特征”名字。
- `core/sanger/batch.py:658-659`：
```python
elif confirmed:
    out = f"合格：编码区蛋白一致；编码区外 {len(confirmed)} 处确证差异（{feats}）"
```
- `app/sequencing_report.py:147-154`：`conclusion.startswith("合格")` → 归入“正确”文件夹。

**实测**（附录 A-启动子）：在 CMV promoter 特征内制造一个高置信替换：
- 网页结论：`✗ 结论：检出 1 处确认差异`
- **批量 Excel：`合格：编码区蛋白一致；编码区外 1 处确证差异（CMV promoter）；测序覆盖 26%`** → 整理包归入“正确”。

另外 `confirmed` 也包含 CDS 内的同义突变，被措辞为“编码区外”，与事实不符。

**影响**：漏报（批量筛克隆时用户只看 Excel 第一列）、同一分析在两个出口给出相反判定。

**改进方案**：建立**元件关键性表**（按特征 type 与名称/qualifier）：
- 关键：promoter、RBS/Kozak、ori、polyA signal、重组位点、抗性 CDS、tag、克隆接头；
- 规则：关键元件内任何 confirmed 差异 → 不合格；unresolved → 待定；非关键/未注释区 → 合格但列出。
- Excel、网页摘要、归档分桶**共用同一个结构化 verdict 对象**（见 5.1），禁止各自拼字符串。

### 4.2【高】部分覆盖的 CDS 也能得到 ✓ / 合格

**代码证据**：`pipeline.py:1482-1486` 覆盖 <99% 时措辞“已测区域蛋白与设计一致”，但 `protein_identical=True`；摘要 `pipeline.py:368-390` 不看覆盖；`batch.py:586-609` 只有“既无完整覆盖 CDS、实测又 <100bp”才判无法判定。

**实测**（附录 A-部分覆盖）：CDS 仅覆盖 34.5% → 网页 **`✓ 结论：构建与设计一致，未检出差异`**，Excel **`合格：与设计一致；测序覆盖 26%`**。

**影响**：漏报。用户以为整个插入片段验证通过。

**改进方案**：引入**验证目标（ROI）**：默认为“插入片段 + 两侧连接 ±50bp”（设计记录里有 `insert_start`），批量模式可在信息表声明。结论按 ROI 覆盖分级：100% 双向/双覆盖 → 可判合格；100% 单覆盖 → 合格（单链）；<100% → “部分验证（缺口 x-y）”，不得给“合格”。

### 4.3【中】CDS 的 ORF 自动校正没有边界，可能整体改写标注

**代码证据**：`pipeline.py:1146-1193` `_find_orf` 在三个读框中找“最长 ORF”，起始密码子包括 `ATG/GTG/TTG/ATT/CTG/ATC/ATA` 七种；`pipeline.py:1358-1359` 直接用结果替换特征坐标，偏移量不设上限；`pipeline.py:1225` 所有宿主一律 `table=11`。

**实测**（合成参考）：标注 1100-1399 被改为 1228-1399（偏移 128bp）；标注 2401-4100（1700bp）被改为 2411-2926（516bp），CDS 覆盖率随之从约 11% 变成 34.5%。真实基因通常有规范起始密码子，此极端情形主要出现在：融合标签片段、无 ATG 的插入、含琥珀终止（非天然氨基酸）的设计、或参考本身有错。

**影响**：误判（阅读框被换掉后的“蛋白一致/不一致”没有意义），且用户只在结论末尾小字看到“已按编码区翻译”。

**改进方案**：只允许在标注起点 ±3bp、**同读框**内调整，且仅限 ATG（原核可加 GTG/TTG）；超出即保留标注并告警“参考 CDS 标注可能有误”；读取 GenBank `/codon_start`、`/transl_table`，按宿主选密码子表。

### 4.4【中】多 read 拼接：有加权投票，没有重叠区一致性报告和双链覆盖要求

**代码证据**：`pipeline.py:964-1100` `_build_consensus` 按列 Q 加权投票得出单一碱基；跨 read 冲突检查只针对 `support_reads == 1` 的变体（`pipeline.py:1945`）。没有“重叠区内各 read 分歧列”清单，也没有“该位点是否被正反两条链覆盖”的统计。

**影响**：当两条 read 在重叠区给出不同碱基且都非 low 时（例如两个克隆混在一起、或一条 read 局部错位），投票静默取胜者；用户看不到分歧。

**改进方案**：输出 `overlap_discordance` 表（参考位、各 read 调用/Q/峰比、加权票差）；对 ROI 计算“双链覆盖率 / 双覆盖率”，并在结论中作为可信度维度；票差 < 阈值的列输出 IUPAC 并列为 unresolved。

### 4.5【低】变体表的氨基酸注释逐条独立计算，同一密码子多处替换时与 CDS 结论不一致

**代码证据**：`annotator.py:114-130` 每个替换只把自己的碱基放进参考密码子。**实测**：参考 `AAA`（K2）中相邻两处替换 A→T、A→G，变体表分别显示 `K2*` 与 `K2R`，而真实密码子为 `TGA`（终止）。CDS 结论因为合并重建是对的，但表格与结论互相矛盾。

**改进方案**：先按密码子聚合同一读框内的替换（MNV），再统一注释。

## 第五层　结果输出与人机交互

### 5.1【高】顶部 ✓/✗/△ 摘要不汇总所有阻断项，需要人通读几十行自由文本

**代码证据**：`pipeline.py:354-390` `_conclusion_summary` 只看 `variants`、`cds_reports`、`has_mixed`、`partial_reads`。poly 计数矛盾/不可判定（`pipeline.py:2517-2522`）、poly 下游信号骤降（`pipeline.py:2312-2328`）、可信区外差异、覆盖缺口、ROI 未覆盖，**都不影响摘要符号**——它们在后面的段落里，摘要仍可能是 ✓。整个 `_build_conclusion` 约 400 行在拼接带“↳”的长字符串。

**影响**：人工负担。用户无法只看摘要，必须逐行阅读；而“✓”又会诱导跳过阅读。

**改进方案**：结论改为**结构化 verdict 对象**：
```json
{"status": "pass|fail|pending|mixed|insufficient",
 "blocking": [{"kind": "unresolved_variant", "ref_pos": 2280, "element": "GeneX CDS",
               "evidence": {...}, "action": "补测 / 看峰图"}],
 "coverage": {"roi": [1001, 1700], "covered": 0.92, "double_strand": 0.40}}
```
摘要由 `blocking` 是否为空机械地导出；文本由 verdict 渲染，前端、Excel、Markdown 报告共用同一对象。

### 5.2【高】关键判定靠中文字符串匹配驱动

**代码证据**

- `pipeline.py:2664`：`has_mixed = any("疑似混合样品" in x for x in mixed_lines)`——摘要是否为 △ 取决于某行文案是否含这 6 个字。单 read widespread 且互检“倾向噪声”时文案不含该词，于是不算混合。

- `sequencing_report.py:150-153`：整理包按结论是否以 `"合格"` / `"不合格"` 开头分桶。

**影响**：任何一次文案润色都可能静默改变判定或隐藏行；已有文案与逻辑多次互相打架的修复记录（KNOWN_ISSUES 中多条“措辞”类修复）。

**改进方案**：判定只读结构化字段（`mixed_profile.class`、`verdict.status`）；文本只做渲染，前端按字段折叠。为此加一个契约测试：改动任何文案不得改变 `verdict.status`。

### 5.3【中】三级置信度实际是二元的，且没有可校准的数值

**代码证据**：`medium` 在所有判定口径中与 `high` 同等计入“确认”（`pipeline.py:363`、`1411`、`batch.py:625`）；`VariantTable.vue:17,23-26` 低置信默认折叠；`_variant_confidence`（`pipeline.py:172-237`）是 14 个 if 分支的硬阈值（Q 15/25/30/40、峰比 30/60/70/80、SNR 5/10、插入峰 0.3/0.6）。pipeline.py 中“核对峰图/人工核对”字样出现 25 次。

**影响**：用户无法据分数排序复核；“低置信”同时包含“几乎确定是噪声”和“很可能是真突变（如 1.1 的 Q50 例）”。

**改进方案**：用逻辑回归/梯度提升（特征：Q、峰比、局部 SNR、局部峰距异常、read 位置、双峰背景 z 分数、支持 read 数与方向、互检结果、是否 poly）输出 `P(真实)`，在真实标注集上校准；行动分四档：自动接受（P>0.99）、自动排除（P<0.01 且有反证）、**看峰图（附定位快照）**、**补测（无第二条 read 可救）**。表格按“需人看”的优先级排序，而不是把 low 折叠。

### 5.6【中】回归测试无法发现上述问题
