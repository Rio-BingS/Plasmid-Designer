## 二、P0：仍会出「假 ✓」

### P0-1 整质粒模式（无 CDS 注释）部分覆盖仍出 ✓「构建与设计一致」
- 实测：3000bp 参考、单 read 覆盖 1–900，**status=pass，✓ 构建与设计一致**。参考上注释的 pUC ori（700–1289 半覆盖 / 1500–2089 完全未覆盖）、AmpR promoter、lac operator 未覆盖时同样 ✓。
- 代码：`verdict.build_verdict` 中 `roi_gap = roi_source != "whole" and roi_measured_pct < 99`——ROI 为整条参考时**直接豁免**覆盖判定；关键元件覆盖只写 `info: element_coverage`，不进入 blocking。
- 与 goal 冲突：T5 要求关键元件输出 full/partial/uncovered 元件级结论；T2 规定 partial = ROI verified <100%。agent 的理由是「单引物测整质粒是常规策略」，这能说明不该判 fail，但说明不了可以说「与设计一致」。
- 修法：整质粒模式下 measured 未达阈值时判 partial，头行写「已测区段一致（x–y），其余未验证」；关键元件 uncovered/partial 进 blocking（kind 用 roi_uncovered，带元件名），status 至少为 partial。

### P0-2 verified 口径从未落地，且出现「pass 但 blocking 非空」
- 实测：CDS 301–1299，verified 99.0%、measured 99.1% → **status=pass，但 blocking 里有 roi_unverified**。头行 ✓，下方又列出阻断项，自相矛盾。
- 代码：同函数注释写明「roi_unverified 阻断明示……均不升状态」；`MIN_VERDICT_COVERED_BP` 闸门仍用 measured。PROGRESS 中 T3/T5 偏差写「语义切换随 T12 复评」，T12 之后没有复评，一直沿用到 P2 闸门。
- 与 goal 冲突：§1「结论、CDS full、批量闸门全部用 verified」；契约上 blocking 非空不应为 pass。
- 修法：要么 roi_unverified 驱动 partial（goal 原意），要么把它降为 info——二选一，不能放在 blocking 里却不影响状态。契约测试加一条：`status == "pass"` ⇒ `blocking == []`。

### P0-3 AF 15–22% 混合在 CDS 内静默 ✓，不留任何记录
- 实测：有效 ORF 内 450 位次等位 AF 0.12/0.15/0.20 → **pass，blocking 空，无未决位点**；AF 0.23 起才判混合。
- 代码：`mixed_model` 阈值 = `max(ratio_floor=0.30, 局部中位 + k·MAD)`——所谓「自适应」只能抬高阈值，不能降低；ratio 0.30 ≈ AF 0.23。而 `verdict`/`mixed_call` 的 `MINOR_AF_MIN = 0.15` 永远收不到 0.15–0.23 的位点，成了死代码。
- 佐证：SANGER_CALIBRATION.md §4 自己的网格显示 ratio_floor 0.20 与 0.30 并列最优，仍保留 0.30。
- 修法：floor 降到 0.18–0.20（在本底干净时）并由局部噪声自适应上调；0.15–floor 区间至少记 unresolved_site，不允许静默。

## 三、P1：结论可信度与实现偏差

### P1-1 基准集是自证式的，「敏感度/特异度 1.0」不能当作验证
- truth.yaml 的 verdict 真值「与场景测试断言同源」，正例只有 14 个位点，全部来自开发时反复调过的场景；CI 阈值（0.95/0.99）是看到 1.0 之后定的。
- T24 提交把 F1/F2/M12 的真值从 pending **改成跟随新输出的 pass**（方向本身合理，但说明真值在跟着算法走）。
- 3 个真实 AB1 的参考由 read 自身 basecall 拼成，不可能有真变异，只能测混合 FPR。
- 修法：另建一批**开发时不可见**的盲测场景（随机种子、随机位置/AF/indel 长度，脚本生成），以及至少一组带设计参考的真实数据；基准与场景库分离。

### P1-2 p_real 不是校准概率
- `variant_score.json` 为手设系数，文档自述与旧 if 树「逐位等价」（一致率 1.0000）；证据-only 拟合 AUC 0.81 被弃用；ROC 在 τ∈[0.01,0.91] 是平线。也就是说 T15「校准 P(真实)」实质是旧规则加了一层连续外皮。
- 建议：UI 不要把它显示成「P(真实)=99.75%」这种百分比，改为档位；等真实数据到位再做真拟合。

### P1-3 端部错误连接 <30bp 不报
- 5′ 端 20bp 错误序列（Q40）→ ✓。阈值处的取舍可以接受，但应至少记 info / 未决。

### P1-4 前端仍有文案解析残留
- 头行与阻断项已改为读 verdict（好）；正文仍按「低置信（」「差异区间…无需核对」字符串分组，低置信行默认折叠，折叠按钮文案仍写「疑似测序噪声/混合峰」，`annotator.py` 四处「低置信度（…疑似伪影…）」话术未改。旧记录兼容可以保留，但新记录应全部走结构化字段。
